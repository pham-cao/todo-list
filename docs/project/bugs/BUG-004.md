# BUG-004: Groups with duplicate ids are kept on load

- Severity: Low
- Priority: P3
- Status: Closed (Verified 2026-11-09)
- Found in: T3 (src/groups.js, uncommitted)
- Related TC: T3-load-duplicate-ids-probe; requirements R55, R59

## Environment
Node unit level, branch task-groups, uncommitted groups.js.

## Steps to reproduce
1. Seed `daily-todo:groups:v1` with `[{"id":"a","name":"X","createdAt":1},{"id":"a","name":"Y","createdAt":2}]`.
2. Call `createGroups(storage).list()`.

## Expected
One entry per id (the first), so a section key, a task groupId and a collapsed entry always map to one group.

## Actual
Both entries are returned, so two groups share id "a". `get("a")`, `update("a", ...)` and `remove("a")` act on the first or on both, and the day list would render two sections with the same key. Duplicate names are kept too (X and x), though the UI cannot create them. Only reachable by hand edited or merged storage.

## Evidence
docs/project/specs/task-groups/qa/evidence/T3-unit/probe.txt (line "load")

## Suggested fix
In the load filter, skip an item whose id was already seen.

## Retest
First per id kept, later duplicates dropped, storage not rewritten (0 setItem). npm test 65 pass. Evidence: docs/project/specs/task-groups/qa/evidence/T3-unit/retest-probe.txt
