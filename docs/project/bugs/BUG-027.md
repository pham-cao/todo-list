# BUG-027: The T7 flip-measure class makes a 200 task day move take about 210 ms

- Severity: High
- Priority: P2
- Status: Closed
- Found in: page-flip T7 (uncommitted src/flip.js and docs/project/design-system.css)
- Related TC: TC-page-flip-T2-15 (existing day-nav test "moving to a day with 200 tasks renders in under 100 ms"); also NFR1 and NFR2 for T8
- Related requirements: R41, NFR1
- Owner: fe

## Environment
Chromium via npx playwright test, desktop and mobile (Pixel 7) projects, `--workers=1` and `--workers=2`, port 4173.

## Steps to reproduce
1. Run `npx playwright test --workers=1 tests/e2e/day-nav.spec.js -g "200 tasks renders"` on the working tree.
2. Compare with a clean copy of HEAD.

## Expected
Moving to a day with 200 tasks renders in under 100 ms, as before the flip (existing test, must keep passing after every task).

## Actual
Received 197 to 220 ms in every run with the T7 diff (both projects when run alone, mobile in the full suite). HEAD passed 3 of 3 runs. Applying only the T7 diff to a copy of HEAD makes it fail 4 of 4 runs.

## Impact
Cause: body.classList.add("flip-measure") sets content-visibility visible on every row, so the one geometry read lays out all 200 rows, which content-visibility auto was there to avoid. Users see a day change that is about twice as slow on a 200 task day, and T8 (speed with 200 tasks) starts from a worse baseline.

## Evidence
- docs/project/specs/page-flip/qa/evidence/TC-page-flip-T2-15/red-day-nav-200-tasks-with-T7-diff.txt
- docs/project/specs/page-flip/qa/evidence/TC-page-flip-T2-15/full-suite-runner-output.txt

## Suggested direction (FE to decide)
Limit the forced layout to the rows that can reach the window, or read only the body top and the window rather than laying out every row.

Result: Verified, then Closed. FE removed the forced layout (ResizeObserver realigns the stage, copied rows get explicit heights).
