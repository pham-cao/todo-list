# BUG-025: With a flip stage present, form controls on the real page get a doubled accessible name

- Severity: Medium
- Priority: P2
- Status: Closed (found by FE during T6, fixed before QA execution, Verified by QA 2026-11-12)
- Found in: page-flip T6 (src/flip.js copy())
- Related TC: TC-page-flip-T6-09 (also T6-10)
- Related requirements: R11, R20
- Owner: fe

## Environment
Chromium desktop, http://localhost:4173, 1440 x 900, --dur-flip 30000ms so the stage stays, tasks seeded for 09/11 and 10/11/2026.

## Steps to reproduce
1. Open the app, make the stage last (set --dur-flip to 30000ms) and press the next day arrow.
2. Read the accessibility tree (ariaSnapshot) of the body.

## Expected
The same tree as on a settled page, the new day only (R11, R20): textbox "Bạn cần làm gì ngày này?", combobox "Nhóm", combobox "Lọc theo nhóm".

## Actual
The leaf copy kept the `for` attribute of its labels, so each leaf label named a real control: textbox "Bạn cần làm gì ngày này? Bạn cần làm gì hôm nay?", combobox "Nhóm Nhóm", combobox "Lọc theo nhóm Lọc theo nhóm".

## Impact
A screen reader user hears leaf text in control names during a flip. Medium: only while the stage plays.

## Evidence
- docs/project/specs/page-flip/qa/evidence/TC-page-flip-T6-09/red-without-fix-HEAD-flip.js.txt (T6-09 fails on the committed flip.js)
- docs/project/specs/page-flip/qa/evidence/TC-page-flip-T6-09/runner-output.txt (passes with the fix)

## Fix
copy() removes both `id` and `for` from the clone (src/flip.js, uncommitted).

## Retest (2026-11-12)
T6-09 fails against HEAD flip.js (scratch copy) and passes on both projects with the fix. T6-10 axe passes. Result: Verified, then Closed.
