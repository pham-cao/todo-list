# BUG-014: In Firefox a move or day change with 200 tasks takes about 190 ms, over the 100 ms of NFR1

- Severity: Medium
- Priority: P3
- Status: Open (found at feature acceptance; decision for the PM: fix, or accept and list in the release note)
- Found in: T11 Firefox run (TC-task-groups-T11-21). The same speed class already fails on main for day navigation (day-nav.spec.js "moving to a day with 200 tasks renders in under 100 ms"), so it is not caused by task groups alone
- Related TC: TC-task-groups-T11-21, TC-task-groups-T11-16, TC-task-groups-T9-26; requirement NFR1

## Environment
Firefox 150 class build from the Playwright cache (firefox-1572), headless, desktop 1280 px, clock fixed 2026-11-09 09:00 +07, python http.server, Linux host.

## Steps to reproduce
1. Run `npx playwright test -c <config with project firefox> -g "200 tasks"` (or seed 200 tasks on today in 20 groups).
2. Wait 500 ms, press Sửa on a task, choose another group, time requestSubmit() plus a forced layout in the page.

## Expected
NFR1: with up to 200 tasks the update takes under 100 ms.

## Actual
Move: 189 ms and 192 ms (two tests). Add passes. Chromium passes with 10 to 50 ms (BUG-002 and BUG-010 fixes use content-visibility, a feature that Firefox of this build does not apply the same way).

## Impact
A short pause on a very heavy day in Firefox. Content is correct, nothing is lost. Caveat: headless run on a shared host.

## Evidence
- docs/project/specs/task-groups/qa/evidence/T11/firefox-suite.txt

## Suggested fix
Profile the move in Firefox; options are keeping row reuse for unchanged rows in sections or limiting forced layout. Or accept the limit and add it to the release note together with the untested Safari and iOS risk.
