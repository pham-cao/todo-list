# BUG-012: The delete blocked note stays open after its group is removed in another tab, and Chuyển tất cả việc on it does nothing

- Severity: Low
- Priority: P4
- Status: Closed (Verified 2026-11-10)
- Found in: task-groups T10 QA (uncommitted); the stale note is from T9, the silent button press is new with T10
- Related TC: TC-task-groups-T10-30; requirements R52, R67

## Environment
Chromium (Playwright), two tabs on the same origin, fixed clock 2026-11-09.

## Steps to reproduce
1. Tab A: Quản lý nhóm, Xóa on a group with tasks (Công ty), so the blocked note opens. Press Chuyển tất cả việc so the move card opens over it.
2. Tab B: delete the group from the groups list in storage (or delete it in the app after moving its tasks away).
3. Tab A: the move card closes (sync). The blocked note stays open, focus on its Chuyển tất cả việc button.
4. Press Enter on that button.

## Expected
The note for a group that no longer exists closes, or the press gives some feedback.

## Actual
The note stays open and the press does nothing, with no message and no focus change. The owner can leave with Đã hiểu or Escape. No data change, no script error.

## Impact
A dead control in a rare two tab case. No data loss.

## Evidence
evidence/T10/probe-other-tab.txt

## Fix and retest (2026-11-10)
Fix: sync closes the blocked note (and the move card first), focus to the row Xóa or Đóng. Retest: e2e test passes 2 of 2 per project in the full suite; mutation check in a scratch copy (guard removed) fails the test on both projects.
