# BUG-009: A group is deleted although another tab has just added a task to it

- Severity: Medium
- Priority: P3
- Status: Closed (Verified 2026-11-10)
- Found in: T9 (src/manage.js `removeGroup`, uncommitted)
- Related TC: TC-task-groups-T9-22 (failed); requirements R52, R54, NFR3

## Environment
Branch task-groups, uncommitted T9 build, http://localhost:4173, Chromium (Playwright), two tabs in one browser context, clock fixed 2026-11-09 09:00 +07, locale vi-VN.

## Steps to reproduce
1. Tab A: groups Công ty, Nhà, Học tiếng Nhật and Sức khỏe, Sức khỏe empty. Open "Quản lý nhóm" and press Xóa on Sức khỏe. The question "Xóa nhóm "Sức khỏe"?" is open.
2. Tab B (same browser): add a task to Sức khỏe. The tasks key now holds one task with that group.
3. Tab A: press "Xóa nhóm".

## Expected
R52: a group that has a task on any day is never deleted. The check at confirm time sees the new task, so the group stays (the blocked message may show) and the stored task keeps a valid group.

## Actual
The group is removed from the groups key. The stored task still carries the id of the missing group, and it shows under Chưa phân nhóm on the next load. No task is lost, but the group the owner sees in Tab B vanishes and R52 and R54 are broken for this order of events.

## Cause (observed)
`askDelete` and `removeGroup` use `store.groupUsage`, which reads the tab's in-memory copy of the tasks. The storage listener in src/app.js only reloads the groups key, never the tasks key, so Tab A cannot see the task.

## Evidence
- docs/project/specs/task-groups/qa/evidence/T9/full-suite.txt
- Automated: tests/e2e/groups.spec.js `test.fail` "a task added to the group in another tab while Xóa nhóm? is open: the group must not be deleted (BUG-009)" (both projects)

## Impact
Low probability (two tabs, a precise order). No data loss. The owner may find a task moved to Chưa phân nhóm.

## Suggested fix
In `removeGroup`, read the tasks key again from storage and count the tasks of the group before deleting. If the count is not 0, close the note and show the blocked note instead. Then remove `test.fail` from the test. The wider stale-tasks behaviour across tabs is older than this feature and is not part of this bug.

## Retest
Retest 2026-11-10: FE re-reads stored tasks in removeGroup and shows the blocked note with fresh n and d; test.fail removed and the test passes in both projects in the full suite (--repeat-each=2: 1008 passed, 0 failed). Result: Verified, Closed.
