# BUG-020: A pointer or finger over the drop strip scrolls the page up when the strip's top edge is above 64 px

- Severity: Low
- Priority: P3
- Status: Closed (Verified 2026-11-11)
- Found in: drag-drop T6 (uncommitted src/drag.js `scrollSpeed`), edge probe with 20 groups; also named in the PM review entry in decisions.md (2026-11-11 drag-drop T6)
- Related TC: TC-drag-drop-T6-06, TC-drag-drop-T6-09; requirement R31 (no scroll over the strip; decision: the zone sits above the strip)
- Owner: fe

## Environment
Chromium, Playwright Pixel 7 project with the viewport set to 360 x 440; 20 groups, 60 tasks; touch through CDP. Unit values by calling `scrollSpeed` in node.

## Steps to reproduce
1. Seed 20 groups and 60 tasks, set the viewport to 360 x 440, scroll the page down 600 px.
2. Long press a row, move the finger to y 200, then to y 5 (over the strip, whose top is at -120).
3. Hold for 700 ms.
Unit level: `scrollSpeed(30, 50)` returns -10; `scrollSpeed(60, 50)` returns -2.

## Expected
Over the strip nothing scrolls (TC-drag-drop-T6-09, decision "the zone sits above the strip").

## Actual
The page scrolls from 600 to 0 while the pointer is over the strip. The up zone (y < 64) is evaluated before the strip check, so it wins over the strip when stripTop < 64. Strip top by screen size with 20 groups: 390 x 844 gives 376, 360 x 800 gives 240, 360 x 640 gives 80 (zones overlap from 16 to 64), 320 x 568 gives 8, 360 x 500 gives -60 (strip taller than the screen). Also, with stripTop below 128 the speed jumps from -1 at y 63 to +8 at y 64 (stripTop 100) because the two zones overlap.

## Impact
Low: only screens up to about 360 x 640 with many groups, no data change, the target under the pointer is still marked. The page moving while the user aims at a label near the top of the strip is confusing. Not reachable at 390 x 844.

## Suggested fix
Return 0 when y >= stripTop before the up zone check (as the PM review entry in decisions.md already says), add a unit case for stripTop below 64, and decide how the zones share the screen when they overlap.
