# BUG-016: The lifted slip drifts away from the pointer and sticks out past the right edge of the screen

- Severity: Medium
- Priority: P3
- Status: Closed (Verified 2026-11-10, T3 retest)
- Found in: drag-drop T3 (uncommitted changes in src/drag.js, design-system.css `.drag-slip`), TC-drag-drop-T3-27 (also affects TC-drag-drop-T3-22 grab point)
- Related TC: TC-drag-drop-T3-27, TC-drag-drop-T3-22; requirement R27 (slip follows the pointer, keeps the grab point); design.md clamp inside the viewport

## Environment
Chromium and Firefox (Playwright), desktop 1280 x 720 and 390 x 700, mouse, light scheme, clock fixed 2026-11-09 09:00 +07, locale vi-VN, npm start on port 4173.

## Steps to reproduce
1. Seed 2 groups and a few tasks (a long task text helps, 200 times "x" at 390 px).
2. Press a row and move the mouse 20 px to lift it.
3. Move the pointer to the bottom right corner of the window (1279, 719).
4. Read `.drag-slip` style.transform and getBoundingClientRect().

## Expected
The slip is clamped inside the screen (design: x between 8 and width minus slip width minus 8) and keeps the grab point under the pointer.

## Actual
style.transform is translate(752px, 652px) (clamp correct) but the box is at left 773.3, top 616.3, right 1295.3, so 15 px outside a 1280 px screen. At 390 px the slip right edge is 402 px (12 px past the screen). Cause: the CSS `rotate: -2deg` property is applied outside the `transform`, so the translate vector is rotated by 2 degrees about the slip centre. The error grows with the pointer position: about +21 px sideways and -36 px up at 1280 x 720. The slip is therefore never exactly at the grab point and the clamp does not hold at the right edge. With reduced motion (rotate 0) it is exact.

## Impact
Cosmetic, no data effect (the page has no sideways scroll: scrollWidth equals innerWidth, and the drop target will come from the pointer position in T4). The slip is up to 36 px away from the pointer, and part of it is cut off on the right on a narrow screen.

## Suggested fix
In follow() set `s.slip.style.translate = ...px ...px` instead of `style.transform` (translate is applied before rotate, so the tilt is about the slip's own centre). Drop the `translate: 0 3px` from the pick-up keyframes or keep it on `transform`; then remove test.fail in the spec.

## Retest

At 390 px with the pointer at the bottom right the slip right edge is 383 px (was 402). New test "the grab point stays under the pointer wherever the pointer goes" shows the slip text keeps its offset from the pointer within 4 px at three far positions.
