# BUG-013: When another tab holds more tasks of the group, Chuyển việc is refused for good with a message that does not say why or what to do

- Severity: Medium
- Priority: P3
- Status: Closed (Verified 2026-11-10)
- Found in: task-groups T10 QA (uncommitted)
- Related TC: TC-task-groups-T10-28; requirements R70, R61

## Environment
Chromium (Playwright), two tabs, tasks key in localStorage, storage available.

## Steps to reproduce
1. Tab A: open Quản lý nhóm, Chuyển tất cả việc on Công ty (3 tasks), pick a target.
2. Tab B (same origin): add a task to Công ty so storage holds 4.
3. Tab A: press Chuyển việc. Press it again. Press Hủy, reopen the card, press Chuyển việc again.

## Expected
The owner learns why nothing moved and has a way forward (for example a line saying another tab added tasks and the page needs reloading, or the tab takes the stored tasks and the sentence updates to the new count).

## Actual
Every try shows "Không thể lưu thay đổi. Chưa có việc nào được chuyển." This reads like a storage failure, and a retry can never succeed, because the tab does not re-read the tasks key (no storage listener for tasks). Only a page reload recovers, and nothing says so.

## What is safe
Nothing is written and no task is lost (stored string unchanged, tested). Refusing is the right data call; the gap is the message and the path. Other writes of this tab (adding a task) overwrite the same stale list without this check, so the move is stricter than the rest of the app.

## Impact
A confused owner in a rare two tab case, with no data loss.

## Suggested fix
Either show a distinct message such as "Một tab khác vừa thêm việc vào nhóm này. Hãy tải lại trang rồi thử lại.", or reload the tasks from storage in this case and update the sentence so the owner can confirm the new count. The wording needs a decision, as R70 fixes the current text for write failures.

evidence/T10/qa-new-tests.txt (test "another tab stored more tasks of the group: the refusal repeats")
