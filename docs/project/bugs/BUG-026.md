# BUG-026: On a scrolled phone page the leaf copy landed up to 246 px off the page

- Severity: Medium
- Priority: P2
- Status: Closed (found by FE during T7, fixed before QA execution, Verified by QA 2026-11-12)
- Found in: page-flip T7 (src/flip.js play())
- Related TC: TC-page-flip-T7-11
- Related requirements: R12, R13
- Owner: fe

## Environment
Chromium, 1440 x 900, 390 x 844 and 360 x 780, a day of 30 rows that wrap to two lines on phones, page scrolled to 1200 px.

## Steps to reproduce
1. Seed 30 rows for today and tomorrow, scroll to 1200 px, wait two frames.
2. Press the next day arrow and compare the leaf label positions with the old rows.

## Expected
The leaf copy lines up with the page through --flip-offset (R13).

## Actual
Rows use content-visibility auto, so the new rows were one rule placeholders in the task of the click; the page read shorter and the window as scrolled up. The leaf landed 246 px (390 px) and 109 px (360 px) off.

## Evidence
- docs/project/specs/page-flip/qa/evidence/TC-page-flip-T7-11/red-on-HEAD-src-246px.txt (T7-11 fails on committed src, scratch copy)
- docs/project/specs/page-flip/qa/evidence/TC-page-flip-T7-11/runner-output.txt (passes with the fix)

## Fix
A flip-measure class sets content-visibility visible for the one geometry read. See BUG-027 for its side effect.

## Retest (2026-11-12)
Red on HEAD src, green on desktop and mobile with the fix. Verified, then Closed.
