# BUG-017: In Firefox the T3 test "a release anywhere cancels" fails after the T4 edit because it releases the pointer above the screen

- Severity: Low
- Priority: P4
- Status: Closed (Verified 2026-11-10)
- Found in: drag-drop T4 (uncommitted tests/e2e/drag.spec.js, test at line 226), Firefox spot check
- Related TC: TC-drag-drop-T3-19 and TC-drag-drop-T3-20 (release on nothing, focus rules); requirement R22
- Owner: fe (test code only; no change in src/ needed)

## Environment
Firefox (Playwright "Desktop Firefox", 1280 x 720), temporary config in the scratchpad (playwright.config.js untouched), clock fixed 2026-11-09 09:00 +07, vi-VN, npm start on port 4173. Chromium passes.

## Steps to reproduce
1. `npx playwright test -c <temp firefox config> tests/e2e/drag.spec.js -g "a release anywhere cancels"`.
2. The test seeds 3 groups and 4 tasks, presses "Cắt tóc" (last row) and moves (40, -150); the page scrolls so that the row is in view.
3. The T4 edit then moves the pointer to the middle of `#page-title` and releases there.

## Expected
The test passes in Firefox as it did before the T4 edit, with no slip, strip or `is-dragging` left.

## Actual
`#page-title` has bounding box y = -160 (it is scrolled above the screen), so the pointer is moved to y = -140 and released there. Firefox does not deliver the `pointerup` for a position outside the viewport, so the drag never ends: 4 leftovers (`html.is-dragging`, slip, strip, placeholder). Fails 3 of 3 runs. With the T3 version of the test (release where the pointer is) it passes (1 passed). The other 30 Firefox drag tests pass, including all 11 T4 drop tests.

## Impact
Test only: the project config runs Chromium, so CI is green. It leaves a Firefox spot check red and shows that a release outside the window leaves the page in drag state in Firefox when the mouse button is released off screen (a real browser keeps delivering mouse events to the page during a held press, so this is likely a test harness limit). T7 (window blur, pointercancel) is the place to cover a lost release.

## Evidence
- docs/project/specs/drag-drop/qa/evidence/T4-regression/firefox-drag-spec.txt
- docs/project/specs/drag-drop/qa/evidence/T4-regression/firefox-offscreen-release-probe.spec.js (prints title y = -160, is-dragging still true after mouse.up)

## Suggested fix
Release over an element that is on screen and not a target (for example the add input or `#summary` after `scrollIntoViewIfNeeded`), or scroll to top before reading the box.
