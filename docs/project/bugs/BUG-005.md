# BUG-005: Section toggle accessible name does not contain its visible text (WCAG 2.5.3 Label in Name)

- Severity: Medium
- Priority: P2
- Status: Closed (Verified 2026-11-10)
- Found in: T4 (src/app.js `updateSummary`, `#group-template`, uncommitted)
- Related TC: TC-task-groups-T4-18 (failed), TC-task-groups-T4-05; requirements R63, NFR6

## Environment
Branch task-groups, uncommitted T4 build, served on http://localhost:4173, Chromium (Playwright), axe-core from the scratchpad (tags wcag2a, wcag2aa, wcag21a, wcag21aa, wcag22aa, best-practice). Seen at 1440, 390 and 360 px, light and dark, in the sections view and the collapsed view. The plain list view is clean.

## Steps to reproduce
1. Seed tasks in two or more groups on 09/11/2026 (for example Công ty and Nhà), open the page.
2. Run axe on the document.

## Expected
No serious or critical violation (TC-task-groups-T4-18, NFR6).

## Actual
Rule `label-content-name-mismatch` (serious) fires on every `.group__toggle`. The visible text is "Công ty 1/3" (group name and count), while the accessible name set by `aria-label` is "Nhóm Công ty, đã hoàn thành 1/3 việc". The visible string "Công ty 1/3" is not a contiguous part of the name, so a voice control user who says the visible text "Công ty 1/3" cannot activate the button (saying only "Công ty" does work). Same result in all 12 sections and collapsed runs.

The approved prototypes `ux/screens/sections.html` and `sections--collapsed.html` produce the same violation, and the name format is fixed by R63. This is therefore a conflict between R63 and WCAG 2.5.3 found in the design, not a coding slip by FE.

## Notes
Checked and fine: heading level 2 containing the button, aria-expanded on every state, Tab order, Enter and Space, focus kept on the toggle, collapsed rows out of the Tab order. The axe `color-contrast` rule stays "incomplete" because of the torn label pseudo element; computed contrast of the label text on its paper is 13.5 to 16.7 in light and 5.7 to 8.8 in dark, count text 7.2 and 7.5, all above 4.5.

## Suggested fix (needs a decision from UX and the owner, then a requirements update)
Option A: make the name start with the visible text, for example "Công ty 1/3, nhóm, đã hoàn thành 1/3 việc" is clumsy; better "Công ty 1/3, đã hoàn thành" is not valid with R63, so change R63 and TC-05 together.
Option B: keep the R63 name and record a waiver, since the toggle is also reachable by the visible group name alone.
Option C: put the count outside the button (inside the h2 but after it) so the visible button text is only the group name, which is contained in the current name.

## Retest (2026-11-10)
FE removed the aria-label. The toggle name now comes from its content: hidden "Nhóm ", the visible name, the visible count and hidden " việc đã hoàn thành", for example "Nhóm Công ty 1/3 việc đã hoàn thành". The visible "Công ty 1/3" is contained unbroken. Verified: axe 18 of 18 runs (3 viewports, light and dark, sections, collapsed, plain) with no violations; accessibility tree shows heading level 2 with that button name; groups.spec 45 passed; full e2e 287 passed, 11 skipped; npm test 65 pass. Evidence: qa/evidence/TC-task-groups-T4-18/axe-t4-retest.json, qa/evidence/TC-task-groups-T4-05/keyboard-sr-retest.txt.
