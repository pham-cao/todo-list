# BUG-006: The colour shown on the open "Nhóm mới..." line goes stale when another page adds a group

- Severity: Low
- Priority: P3
- Status: Closed (Verified 2026-11-10)
- Found in: T5 (src/app.js, `storage` listener and `openNewGroup`, uncommitted)
- Related TC: TC-task-groups-T5-30 (failed); requirements R10, R15, R63 (storage event path, beyond design for R21)

## Environment
Branch task-groups, uncommitted T5 build, http://localhost:4173, Chromium, desktop and mobile projects, two pages of one browser context.

## Steps to reproduce
1. Seed one group "A" (yellow). Open page A and choose "Nhóm mới..." in the add form. The new line shows a pink swatch (next colour).
2. In page B (same browser, same origin) add a second group, so the groups key becomes [A yellow, B pink].
3. Look at the swatch on the open line in page A.

## Expected
The swatch shows the colour the group will get now, which is green (the colour after pink), as R15 says the line shows the next colour.

## Actual
The choice list refreshes (A, B) and the typed text stays, but the swatch stays pink. Creating the group then gives it green, so the preview does not match the result.

## Evidence
- docs/project/specs/task-groups/qa/evidence/TC-task-groups-T5-30/probe-output.txt
- Automated: tests/e2e/groups.spec.js, `test.fixme` "another page adds a group: the open line swatch shows the new next colour (BUG-006)"

## Impact
Cosmetic. The colour is only a preview, nothing is lost and no data is wrong. Rare path (two pages, one with the line open).

## Suggested fix
In the `storage` listener, when `newLine` is open, set its swatch to `nextColor(groups.list())` after rebuilding `groups`. Then remove `.fixme` from the test.

## Retest (2026-11-10)
FE updates the open line swatch to nextColor in the storage listener. The test that was `test.fixme` now runs and passes (desktop and mobile). Verified, then Closed. Full e2e 331 passed, 11 skipped; npm test 65 pass. Evidence: qa/evidence/TC-task-groups-T5-30/e2e-full-run-retest.txt.
