# BUG-024: Two auto scroll tests compare scrollY to a whole number and fail in Firefox at the page end (1363.8 against 1364)

- Severity: Low
- Priority: P4
- Status: Open
- Found in: drag-drop T8 Firefox spot check (tests/e2e/drag.spec.js, written in T6, not changed in T8)
- Related TC: TC-drag-drop-T8-16 (NFR6); T6 auto scroll tests
- Owner: fe
- Type: test code only, no change to the app

## Environment
Firefox (Desktop Firefox device), headless, host in powersave, scratchpad config (playwright.config.js not changed), http://localhost:4173, 1440 x 900.

## Steps to reproduce
1. Run `npx playwright test -c <scratchpad>/ff8.config.mjs --workers=1 tests/e2e/drag.spec.js -g "auto scroll"` with only the firefox project.
2. Watch "resting above the strip scrolls down with the down cue, the strip stays put, and it stops at the page end" (line 673) and "a section the scroll brings under a still pointer becomes the target, and a release drops there" (line 773).

## Expected
The page scrolls to its end and the test sees it there.

## Actual
The page does reach its end, but Firefox reports scrollY as 1363.8 (and 1803.8) where the test expects the whole number 1364 (and 1804), so `expect.poll(...).toBe(...)` times out after 5 s. Chromium reports whole numbers, so both pass there. No user visible problem: the page is at its end within 0.2 px and the drag, the down cue and the drop worked in the same runs.

## Impact
Low. The suite runs on Chromium only, so nothing is red today. It would fail at once if a Firefox project is added later.

## Evidence
- docs/project/specs/drag-drop/qa/evidence/TC-drag-drop-T8-16/firefox-drag-spec.txt
- docs/project/specs/drag-drop/qa/evidence/T8/ff8.config.mjs (the temporary config)

## Suggested fix
Compare with a tolerance, for example `Math.abs(scrollY - end) < 1`, or round both values, in those two tests. The axe test crashing Firefox is a separate known item in decisions.md and not part of this bug.
